# Beginner Usability and Consistency Review

Date: 7 October 2026  
Edition reviewed: Draft v0.3  
Review type: AI-assisted editorial and internal-consistency review

## Purpose

Make the first encounter understandable to a non-specialist while preserving the Core, technical controls, and claims limits established in Draft v0.2.

## Changes and disposition

| Issue | Disposition in v0.3 |
|---|---|
| The README mixed an ordinary first session with a long implementation sequence | Lead with the purpose and a route table; move implementation steps to their own guide |
| The short route ended before any observable check | Add a retrieval/interpretation check, a harmless behavior sample, and a record of the actual outcome |
| The portable prompt imposed formal Charter outputs on Card users | Separate Card, full Charter, and revision outputs and required source files |
| Card and formal Charter revisions could be confused | Distinguish personal wording confirmation from authenticated adoption and supersession |
| Framework edition, Core version, and personal document revision were easy to conflate | Explain each separately and preserve the existing Core digest |
| Portability could imply automatic memory or enforcement | Separate availability, retrieval, interpretation, behavior, and host controls; add handover requirements |
| Data and consequential-use screening did not consistently lead to existing control requirements | Align the scope routes with protected-action and deployment rules |
| The new ordinary check could conflict with sandbox evaluation requirements | Define a narrow invented-text, verified no-tool route; retain isolated sandbox conditions for adversarial, cross-model, tool, and control evaluation |
| A Card did not identify its exact Core after transfer | Prefill the Core version and digest in both the template and worked example |
| Formal adoption terminology was inconsistent | Align the glossary, lifecycle, and Charter; confirmed wording may remain formally draft |

These checks detect document/package issues; they cannot establish secure execution, user comprehension, legal sufficiency, or future behavior.

No live model, cross-model comparison, user study, accessibility certification, independent expert assessment, or control deployment was performed as part of this usability revision. Examples clearly separate expected responses from actual results and leave their results unrun.
